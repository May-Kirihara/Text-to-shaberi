# ストリーミングモード（喋りながら順次TTS / speak_stream）ユーザーガイド

マイクに**話している途中から**、句の切れ目ごとに認識→合成を先行させ、**1本の途切れない音声**として返すモードです。発話を終えてから丸ごと処理する従来の「発話単位」モードに比べ、**最初の音が出るまでが短く**、長い発話ほど体感が滑らかになります。

> このモードは設計上 `docs/IMPL-SPEAKSTREAM*.md` の Phase A/B に対応します。本書は**使う人向け**の説明です。

---

## 1. 2つのモードの違い

| | 🟦 発話単位モード（既定） | 🟩 ストリーミングモード |
|---|---|---|
| 区切り方 | 話して**黙ったら**1発話まるごと送る | 話している途中の**句の切れ目**で逐次送る |
| 最初の音まで | 発話終了 → STT → TTS（発話が長いほど待つ） | 最初の句の切れ目で先行開始（発話長に依存しにくい） |
| 出力 | 発話ごとに1音声 | **1本の連続音声**（句をまたいで途切れない） |
| 向く場面 | 短い一文・確実さ重視 | 長め・喋りながら流したい・配信 |
| サーバ要件 | 不要 | **サーバが `speak_stream` 対応**であること |

どちらも**マイク／VAD はクライアント側**で動き、サーバへ送るのは音声だけです。発話単位モードは従来どおり残っています（無効化していません）。

---

## 2. 使い方

1. クライアントを起動し、サーバに接続する（ステータス行に `接続 ✓` が出る）。
2. メイン画面の**モード切替トグル**で「発話単位」⇄「ストリーミング」を切り替える。
3. 🎤 トグルを ON にして話す。句の切れ目ごとに `🎤→ 認識文` がログに出て、TTS が**順次**流れます。
4. 話し終えてしばらく黙ると、ストリーム全体が終了します。

- 既定でストリーミングにしたい場合は、⚙ 設定の「**既定でストリーミング**」を ON（`client.toml` の `[mic].stream_mode = true`）。
- 再生中のフィードバック防止のためのマイク一時停止は、**発話単位モードのときだけ**働きます（ストリーミング中は喋り続ける前提のため止めません）。

### モード切替トグルがグレーアウトして押せない

これは**サーバ側が `speak_stream` 対応を申告していない**ときの正常な抑止です。クライアントは接続時にサーバの機能（`ready.features.speak_stream`）を見て、対応時のみトグルを有効化します。

主な原因と対処：
- **サーバ（特に Docker イメージ）が古い**：speak_stream 導入前のビルドのまま動いている。→ orchestrator を作り直して再起動：
  ```bash
  docker compose build orchestrator
  docker compose up -d orchestrator
  ```
- ネイティブ起動なら、最新コードで `uv run text-to-shaberi-server` を起動し直す。

## 3. 仕組み（ざっくり）

```
あなた:  「今日はいい天気ですね␣␣␣で、午後は出かけます␣␣␣␣␣␣（無音）」
              └ 句の切れ目で切る ┘        └ 句で切る ┘     └ ここで終了 ┘
クライアント:  seg0 ─┐         seg1 ─┐
                     ▼               ▼
サーバ:    STT(seg0)→TTS(seg0) ┐ STT(seg1)→TTS(seg1) ┐
                               ▼                      ▼
再生:      ───────── 1本の連続音声（seg0 → seg1 …） ─────────►
```

- 句の切れ目（**サブseg無音ms** ぶんの短い無音）でその句を確定し、**先にSTTへ**投げます（次の句を話している間に処理が進む＝先行）。
- 認識結果は**話した順**に並べ直してから合成・再生するため、順番が入れ替わりません。
- 全体の無音が一定（**発話末無音ms**）続くとストリーム終了。再生は **1本のまま**で、句の境界で切れ目を作りません。

> 現在の実装は同時 TTS = 1 本（N=1）です。複数 TTS の並列生成（N≥2）は将来拡張の予定です。

## 4. 設定項目とチューニング

⚙ 設定ダイアログ「マイク」内の項目です（保存先は `client.toml` の `[mic.vad]`）。

| 設定ラベル | 内部キー | 既定 | 効くモード | 役割 |
|---|---|---|---|---|
| VAD感度(0-3) | `aggressiveness` | 2 | 両方 | 大きいほど無音判定が厳しい（雑音に強い／小声を切りやすい） |
| 最小無音ms | `min_silence_ms` | 500 | **発話単位のみ** | 黙ってからこのms分で1発話を確定 |
| パディングms | `speech_pad_ms` | 150 | 両方 | 発話の**頭が切れない**ためのプリロール（遅延ツマミではない） |
| サブseg無音ms | `seg_silence_ms` | 250 | **ストリーミング** | 句の切れ目を検出する無音長（**初動の主役**） |
| 発話末無音ms | `end_silence_ms` | 500 | ストリーミング | ストリーム全体を終える無音長 |
| 最小seg ms | `seg_min_ms` | 400 | ストリーミング | これ未満の短すぎる句は送らない（断片化防止） |
| 最大seg ms | `seg_max_ms` | 2500 | ストリーミング | 無音が来なくてもこの長さで強制的に区切る |
| ゲート閾値 | `gate_threshold` | 200 | 両方 | この音量未満は無音扱い（息・環境音の床） |

### 「速くしたい」ときに触るツマミ

- **発話単位モード** → `最小無音ms` を下げる。黙ってから確定までが短くなります。
- **ストリーミングモード** → `サブseg無音ms` を下げる。最初の句の確定が早まり、**最初の音が出るまで**が短くなります。`最小無音ms` はストリーミングでは**使われません**。

`パディングms` は速度のツマミではありません。下げると速くなるのではなく**発話の出だしが欠ける**だけなので、遅延目的では触らないでください。

### トレードオフと下限

- `サブseg無音ms` / `最小無音ms` を小さくしすぎると、**フレーズ途中の息継ぎ・ためで切れて**断片化し、STT 誤認やプロソディのブツ切れにつながります。
- VAD のフレームは **30ms 刻み**（`frame_ms`）なので、無音系のms はその粒度でしか効きません。
- **`発話末無音ms` は `サブseg無音ms + 60ms` 以上に自動クランプ**されます（句の切れ目より早く全体終了しないため）。
- 話し終わりからストリーム終了までの無音は、おおよそ **`サブseg無音ms + 発話末無音ms`**（既定で約 0.75 秒）です。

### 初動を詰める推奨スタート値（ストリーミング）

| 項目 | 既定 | 試す値 |
|---|---|---|
| サブseg無音ms | 250 | **180〜200** |
| 発話末無音ms | 500 | 350 前後（上の下限に注意） |
| 最小seg ms | 400 | 300（断片化が気になれば戻す） |

> ⚠️ **定常状態の「途切れなさ」は VAD では決まりません**。喋り続けている間ずっと滑らかかどうかは、**サーバの生成が追いつくか（生成 RTF < 1）**で決まります。VAD のツマミが効くのは「最初の音が出るまで」の初動だけです。生成が間に合わないと、ツマミをいくら詰めても途中で詰まります。

## 5. うまくいかないとき

| 症状 | 主な原因 | 対処 |
|---|---|---|
| モードトグルがグレー | サーバが `speak_stream` 非対応（古いビルド／Docker） | §2 末尾参照（orchestrator を再ビルド・再起動） |
| 短い相づちが認識されない | `最小seg ms` より短い句は送られない | `最小seg ms` を下げる |
| フレーズが途中でブツ切れ | `サブseg無音ms` が小さすぎ／`VAD感度`高すぎ | 無音msを上げる／感度を下げる |
| 発話の頭が欠ける | `パディングms` が小さすぎ | `パディングms` を上げる（例 200〜250） |
| 喋り続けると音が詰まる・遅れる | サーバ生成が追いつかない（RTF≧1） | サーバ側 TTS/STT 負荷を下げる・短文で区切る |
| 息や環境音で誤起動 | `ゲート閾値` が低い／`VAD感度`が低い | 閾値・感度を上げる |

---

## 6. 既知の制限

- 同時 TTS は 1 本（N=1）。複数並列生成（N≥2）は将来拡張。
- 句の前文脈（`prev_tail`）を STT 精度向上に使う仕組みは未使用（型のみ用意）。
- 体感・アンダーラン・RTF の実機チューニングは、実マイク＋実 GPU サーバで詰める前提です。
